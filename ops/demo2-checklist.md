# จุดสาธิต 2 — รายการทดสอบบนอุปกรณ์จริง (P3-12)

ใช้ preview `https://phase-3.kemi-classroom.pages.dev` กับ **บัญชีทดสอบ** (ครูทดสอบ / นักเรียนทดสอบ ที่อยู่ใน Google Test users) และงานสมมติในห้อง `เคมี 5/4` เท่านั้น — ห้ามใช้ข้อมูลหรือรูปงานของนักเรียนจริง

> **เพดาน B2 รายวันใช้ร่วมทั้งบัญชี** (ดาวน์โหลด 1 GB · Class B 2,500 · Class C 2,500 ต่อวัน รีเซ็ต 07:00 น.) — ทดสอบตามรายการนี้รอบละไม่กี่ไฟล์ อย่าวนเปิดไฟล์ใหญ่ซ้ำ ๆ ถ้าระหว่างทดสอบเห็นข้อความ “วันนี้เปิดไฟล์ครบโควตาของระบบแล้ว…” ให้หยุดแล้วแจ้ง Claude

## เตรียม (ครู บนคอม)

1. สร้างการบ้านใหม่ชื่อ `ทดสอบอุปกรณ์ <วันที่>` คะแนน 10 กำหนดส่งพรุ่งนี้ รายละเอียดใส่สูตรที่มีตัวห้อย/ตัวยก เช่น H₂SO₄, Fe³⁺, 10⁻³ แนบไฟล์โจทย์ PDF ที่ชื่อเป็นภาษาไทย 1 ไฟล์ (เช่น `แบบฝึกหัด กรด-เบส.pdf`)
2. เตรียมรูปไว้ในแต่ละเครื่อง:
   - รูปถ่ายกระดาษที่เขียนสูตรเคมีตัวเล็ก ๆ ด้วยปากกา (มีตัวห้อย/ตัวยก) — ถ่ายด้วยกล้องปกติของเครื่อง
   - (iPhone) รูปที่เป็น **HEIC** — ตั้งค่า > กล้อง > รูปแบบ > **ประสิทธิภาพสูง** แล้วถ่ายใหม่
   - รูปที่ใหญ่เกิน 20 MB 1 รูป (เช่นรูปพาโนรามา หรือรูปจากกล้องที่ความละเอียดสูงสุด — ดูขนาดในแอปไฟล์ก่อน) — ถ้าหาไม่ได้ข้ามข้อนี้แล้วบอก Claude

## (ข) อุปกรณ์จริง — ทำทุกเครื่อง (iPhone, Android, แท็บเล็ต, คอม)

ล็อกอินบัญชีนักเรียนทดสอบ (เครื่องละครั้ง) แล้วทำตามลำดับ:

| ข้อ | ทำ | ผลที่ควรได้ |
| --- | --- | --- |
| 1 | เปิดการบ้าน `ทดสอบอุปกรณ์` → กด **เปิดดู** ไฟล์โจทย์ | เปิดได้ ชื่อไฟล์ภาษาไทยถูกต้อง |
| 2 | กด **ดาวน์โหลด** ไฟล์โจทย์ | ไฟล์ที่ได้ชื่อภาษาไทยถูกต้อง (ไม่เป็น `%E0…` หรือ `download`) |
| 3 | แนบรูปที่เกิน 20 MB | ถูกปฏิเสธทันทีพร้อมข้อความ ไม่เริ่มอัปโหลด |
| 4 | แนบรูป 3 รูป (รูปสูตรเคมีอย่างน้อย 1 รูป; iPhone: รูป HEIC) → **ส่งงาน** | ส่งสำเร็จ สถานะเปลี่ยนเป็นส่งแล้ว |
| 5 | (เครื่องที่สองขึ้นไป) **ส่งแก้** — เก็บรูปเดิม 2 รูป เปลี่ยนรูปที่ 3 | ส่งแก้สำเร็จ แถบความคืบหน้าขึ้นแค่รูปใหม่ (2 รูปเดิมไม่อัปโหลดซ้ำ) |

แล้วสลับเป็นบัญชีครูบนคอม → หน้า **สถานะการส่ง** ของงานนี้ → เปิดงานส่งของนักเรียนทดสอบ:

| ข้อ | ทำ | ผลที่ควรได้ |
| --- | --- | --- |
| 6 | ดูรูปสูตรเคมีที่นักเรียนส่ง ซูมดูตัวห้อย/ตัวยก | อ่านออกชัดหลังย่อ (จดว่าอ่านได้/อ่านยาก ต่อเครื่อง) |
| 7 | รูปจาก iPhone (HEIC) | แสดงเป็นรูปปกติ ไม่หมุนผิดด้าน |

**จดกลับมาให้ Claude (ต่อเครื่อง):** ชื่อรุ่นเครื่อง + เบราว์เซอร์ · ข้อ 1–7 ผ่าน/ไม่ผ่าน · ถ้าไม่ผ่านให้ถ่ายหน้าจอข้อความที่ขึ้น · ข้อ 6 อ่านตัวห้อยได้ชัดไหม

## (ค) ที่โรงเรียน — Wi-Fi โรงเรียน

ใช้เครื่องที่นักเรียนจะใช้จริงมากที่สุด (มือถือ/แท็บเล็ต) ต่อ **Wi-Fi โรงเรียน** (ปิดเน็ตมือถือ):

1. ส่งแก้ด้วยรูปถ่ายใหม่ 3 รูป (ถ่ายตอนนั้นเลย) — **จับเวลาด้วยนาฬิกาจับเวลา** ตั้งแต่กดปุ่มส่งจนขึ้นว่าส่งแล้ว
2. ทำซ้ำ 3 ครั้งในช่วงเวลาต่างกัน (เช่น ก่อนเข้าเรียน · พักกลางวัน · ช่วงคาบที่นักเรียนใช้เน็ตพร้อมกัน)
3. ถ้ามีครูอยู่ด้วย: ให้ครูเปิดหน้าสถานะการส่งบนคอมโรงเรียน เปิดดูงานที่เพิ่งส่ง 1 ครั้ง

**จดกลับมา:** เวลาที่วัดได้แต่ละครั้ง (วินาที) + ช่วงเวลา + ชื่อเครื่อง · มีครั้งไหนค้าง/ล้มไหม และข้อความที่ขึ้น · ครูเปิดดูไฟล์บนคอมโรงเรียนได้ไหม

Claude จะเทียบกับเวลาที่ฐานข้อมูลบันทึกเอง (ขอ batch → ไฟล์สุดท้าย ready) จาก SQL ด้านล่าง

## หลังวันใช้งานจริง — เทียบตัวนับกับหน้า Caps & Alerts ของ B2

1. เว็บ Backblaze → **Caps & Alerts** → จดตัวเลข **วันนี้** (ก่อน 07:00 น. วันถัดไป): Daily Download Bandwidth (GB) · Class B Transactions · Class C Transactions
2. บอก Claude ให้รัน SQL นี้กับ kemi-dev (อ่านอย่างเดียว) แล้วเทียบ — หรือวางใน Supabase Dashboard → SQL Editor ของ `kemi-dev` เอง:

```sql
-- ตัวนับคำขอ B2 รายวันของระบบ (วันตาม UTC — วัน B2 รีเซ็ต 00:00 UTC = 07:00 น.)
select day, source, class_b_requests, download_bytes, copy_bytes
from public.b2_daily_usage
where day >= (now() at time zone 'utc')::date - 1
order by day, source;

-- เวลาอัปโหลดต่อชุด (ขอ batch → ไฟล์สุดท้าย ready) ของวันนี้ — ใช้เทียบกับเวลาที่จับมือที่โรงเรียน
select b.created_at at time zone 'Asia/Bangkok' as started,
       count(a.id) as files,
       sum(a.size_bytes) as bytes,
       extract(epoch from max(a.ready_at) - b.created_at)::int as seconds
from public.upload_batches b
join public.assets a on a.upload_batch_id = b.id
where b.created_at >= now() - interval '1 day'
group by b.id, b.created_at
order by b.created_at;
```

3. เทียบ: Class B ของ B2 ≈ ผลรวม `class_b_requests` ทุกแหล่ง · ดาวน์โหลดของ B2 ≈ ผลรวม `download_bytes` (+ `copy_bytes` ถ้า B2 นับ CopyObject เป็นดาวน์โหลด — ข้อนี้คือสิ่งที่ต้องการรู้) — ส่งตัวเลขทั้งสองฝั่งให้ Claude ปรับงบใน TECHNICAL_DESIGN 9.3
